## Как устроен сайт и деплой

- Весь сайт — один файл `index.html`. Это **фрагмент без doctype/head**:
  `<!doctype html>`, `<html lang="ru">`, meta charset/viewport/og и фавикон 🎯
  добавляет workflow `.github/workflows/pages.yml` при сборке.
- Пуш в ветку `claude/targeting-course-website-7cmbmx` → GitHub Actions →
  GitHub Pages: **https://kembll.github.io/Claude/** (обновляется за 1–2 минуты).
- Фото наставника вшито в `index.html` как base64 data-URI (~400 КБ, строка
  очень длинная — Read этого диапазона строк падает по токенам, работать через
  Grep/Edit). Копия фото: `assets/author.jpg`.
- После каждой правки: commit → push → сказать владельцу «обнови через 1–2
  минуты» (на телефоне потянуть страницу вниз / Cmd+Shift+R).

## Железные правила (нарушение = злой владелец)

1. **Десктопное фото-карточку в хиро не трогать**: блок помечен комментарием
   «ФОТО НАСТАВНИКА — НЕ ИЗМЕНЯТЬ». Размер, колонка .78fr, кадрирование —
   зафиксированы. Менять можно только по прямой просьбе.
2. **Эталоны масштаба.** Скрипт `fit()` в конце `index.html`:
   - десктоп приводится к макету 1440×830 (zoom при z>1.02);
   - телефоны приводятся к эталону **430pt** (айфон владельца) через
     `zoom = innerWidth/430`. Сайт обязан выглядеть одинаково на всех
     устройствах — это принципиальное требование владельца.
3. Мобильная и десктопная вёрстки различаются через media `≤1020px` и `≤560px`.
   Все мобильные надстройки (фото-хиро, таймер, бургер) на десктопе скрыты —
   не ломать десктоп мобильными правками и наоборот.

## Как проверять правки (обязательно перед пушем)

Playwright установлен: `require('playwright-core')`,
`executablePath:'/opt/pw-browsers/chromium'`, `args:['--no-sandbox']`.
Локальный `index.html` — фрагмент без viewport-меты, поэтому для мобильных
тестов **обязательно собирать обёрнутую копию** (как это делает деплой):
```
{ printf '%s\n' '<!doctype html>' '<html lang="ru">' '<meta charset="utf-8">' \
  '<meta name="viewport" content="width=device-width, initial-scale=1">'; \
  cat index.html; printf '%s\n' '</html>'; } > /tmp/wrapped.html
```
Скриншоты: мобайл 430×932 (эталон), 390×844; десктоп 1440×900 и 1920×950.
Секции скрыты reveal-анимацией — перед fullPage-скринами выполнить в странице:
`document.querySelectorAll('.reveal').forEach(el=>el.classList.add('in'))`.

## Заявки (форма)

Цепочка: форма сайта → `fetch(LEAD_URL)` (Google Apps Script владельца,
`text/plain` без preflight, `keepalive:true`, успех показывается мгновенно) →
скрипт шлёт в Telegram (бот `@targetologia_leads_bot`, chat_id `836651005`)
и пишет строку в CRM — Google-таблицу «Заявки Курс - Таргетология»
(статусы: Новый/Связался/Думает/Оплатил/Отказ + цитата-подпись).
**Токен бота в репозитории не хранить** — он живёт только внутри Apps Script.
Прямой `api.telegram.org` с сайта не использовать — у части провайдеров РФ он
заблокирован (из-за этого и появился прокси-скрипт).
